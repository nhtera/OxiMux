## Editor

**PDFs open in the editor pane.** A `.pdf` is no longer refused: it opens as a
scrolling document with a page rail, rasterized by `hayro` — a pure-Rust
renderer, so nothing native ships alongside it. The document is parsed once and
each page is rasterized off the UI thread; the previous page's texture is
dropped from the atlas on swap and when the tab closes.

Large scans were the hard case and are handled explicitly. A page never renders
wider than the pane can show: measured against a 2480 × 3508 pt bilevel scan —
the shape scanner drivers emit — the naive path was a 4960 × 7016 bitmap and
139 MB for a single page. The render scale is now one point per logical pixel,
reduced to fit the pane, times the editor zoom, and nothing is requested until
a layout probe has reported the pane's width, so an oversized page is never
rasterized at a size the pane cannot show — not even for the first frame.

Opening is asynchronous too. A 283 MB scan read in ~50 ms warm and parsed in
0 ms, so the parse was never the cost; the read was, and it scales with the
file. A `.pdf` mid-export reads back truncated, and is retried on the same
backoff as any transient read error rather than reported as corrupt.

The keys follow a reader: ↑/↓ scroll within a page, PageUp/PageDown (and Space)
scroll a viewport and step to the neighbouring page once the current one is at
its edge, ←/→ step pages outright, Home/End jump to the first and last.

## Agents

**The Claude picker, fast mode and onboarding follow the installed CLI.** The
model list is read from the CLI that is actually installed rather than from a
list compiled into the app, and the fast-mode toggle now mirrors the CLI's own
state: the connection reads `fast_mode_state` off the `system/init` line
instead of showing what OxiMux seeded. Fast mode also picked up a bolt icon.

**A live agent's prompt outranks the stored progress line in the rail.** The
progress line was taking the second row unconditionally. It is a snapshot with
no timestamp — last write wins — so a comment written half an hour ago kept
asserting itself while the agent had moved on. The prompt is what is happening
now and cannot lie, so while an agent runs, it wins.

## Settings

**Every launchable agent gets an environment, not just four.** The hard-coded
four-entry roster is gone; membership now has one answer, composed from the
registry adapters, the ACP presets and any `[agents.<id>]` block that declares
an ACP transport. `Custom`, the presets and hand-configured ACP agents get the
environment editor and the profiles they were always resolvable for.

**Agent profiles get a list they can be managed from.** The environment card
advertised named profiles but offered two chips and a text field — no way to
see what a profile did, and no way to rename, duplicate or delete one. It is
now a list, one row per profile carrying a résumé of what it launches with,
with the three operations a named thing needs.

**A usage meter row per agent account.** The meter reported one account's rate
limits; two providers do not share a limit, so there was never a single number
to show. Every account configured on the machine now gets a status-bar segment
and a popover block. The second source has no usage endpoint and needs none —
its CLI journals the rate-limit windows verbatim into the session rollout, and
that is read off disk.

## CLI

**`oximux skills ls|get|install`** serves two guides — driving the CLI, and
running a team — embedded in the binary. No runtime, no network, no host: the
version that ships the guide is the version that ships the parser, so a guide
cannot describe a verb the binary lacks.

**`oximux agent hooks on|off|status`** turns the status hooks on for the agent
CLIs from the terminal. Offline by construction: it reads and writes the
agents' own config files and never contacts a host, so it answers when the app
is down — which is when a misbehaving hook is actually being chased. `status`
prints which file it read to decide, even when it found nothing.

**`oximux schedule create --cron "0 9 * * 1-5"`** — the three preset cadences
could not say "weekdays at 09:00". Cron expressions are evaluated in the host's
local zone like every other cadence, and an expression that parses cleanly but
can never fire (`0 9 30 2 *`) is refused at construction rather than sitting
there looking armed.

**Each role in a team run can pick its own agent and model**, with
`--role-agent NAME=AGENT_ID` and `--role-model NAME=MODEL`. A role named by
neither falls back to `--agent` and then to the host's default. A flag naming a
role that no `--role` declared is a usage error listing the roles that exist,
raised before the RPC rather than after the run has started.

## Browser

**A picked element and its crop go to the chat, not a terminal.** Picking with
`A` used to bracketed-paste the text into a PTY and leave the screenshot on the
clipboard, so the two could never arrive together and neither reached a surface
that can hold an image. The capture now lands in the Agent Chat composer as a
`@browser <selector>` chip with the crop attached, and nothing is sent until
you type the actual question. A workspace with no chat tab still falls back to
the old paste, text only.

## Fixes

- **A keystroke no longer reaches the shell twice.** A key the terminal pane
  encoded and sent itself was written to the PTY a second time: GPUI's macOS
  window reads a propagating key event as unhandled and hands the same native
  event to the platform text-input path, which writes to the PTY as well.
- The work-phase chip in the rail no longer shrinks.
- A long setting description wraps instead of erasing its control, and the
  default-agent picker stacks before it starves its own label.
- An agent configured only through a profile says so instead of appearing
  unconfigured.
